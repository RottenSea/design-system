# 准则

一条准则就是一条使用规则。写得好的话，人可以照做，agent 可以照用，工具可以检查。

## 一条规则一句话

每条准则是一句话，加上要求级别：

| 级别 | 含义 |
| --- | --- |
| must（必须） | 必须遵守，违反就是 bug |
| should（应当） | 默认这样做，除非有理由不这样做 |
| may（可以） | 允许，可选 |
| should not（不宜） | 尽量避免，除非有理由 |
| must not（禁止） | 绝不能这样做 |

这几个级别和标准文档里的关键词用法一样。要有意识地使用：标成“必须”却没人检查的规则，迟早会被违反。

准则分成两组：**何时使用**（这东西本身该不该用）和**如何使用**（选定之后怎样用对）。

## 写明理由，写明怎么检查

- **依据**：写明规则遵循的外部来源，例如某条 WCAG 成功标准。有理由的规则，遇到规则没预料到的情况时更容易判断。
- **检查方式**：写明这条规则是自动检查、借助工具检查，还是人工检查。自动检查要写出具体是哪一项：测试、lint 规则，或者每次构建都跑的对比度检查。

## 共用规则只写一次

适用于许多组件的规则，例如“每个可交互元素都有可见的焦点指示”，只写在一处，组件页链接过去，不重复写。

## 示例

> **如何使用**
>
> - **必须**：按钮文字写它执行的操作，例如“保存草稿”。检查方式：人工审阅。
> - **应当**：每个页面只放一个主要按钮。
> - **禁止**：用带点击事件的 `div` 拼出按钮。依据：WCAG 2.2 成功标准 4.1.2 名称、角色、值。

## 来源

[DSDS 的准则分节](https://designsystemdocspec.org/)，其中定义了要求级别、何时使用和如何使用的分组、依据以及检查方式。
