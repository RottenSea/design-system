# Agent notes for this repo

Design systems, each in `systems/<name>/` with its own version, and a Starlight docs site in `docs/`. The README covers commands and releasing; these notes cover what the config does not explain and what has gone wrong before.

## Working here

- Commit each change without asking, and keep history: no amending or rewriting pushed commits. Ask before pushing: a push to `main` runs CI and redeploys the docs site, and a `<system>-v<version>` tag publishes a release.
- Write repo prose without the owner's name ("the design systems in this repository"). Repo URLs, the jsDelivr font URLs and the `@rottensea/` package scope are identifiers and stay.
- `pnpm check` at the root validates tokens, type checks the docs and runs every system's tests.

## A system's folders

| Folder | What it is |
| --- | --- |
| `tokens/` | Hand-written DTCG token files and the resolver |
| `dist/` | `tokens.css` generated by Terrazzo. Not committed; it ships in the release tarball |
| `src/styles/` | Hand-written CSS. The `exports` map in `package.json` keeps the public paths short (`index.css`), so files can move without breaking sites |
| `src/components/` | Astro components, exported one by one and all together from `components` |
| `src/markdown/` | The remark plugin. Plain JavaScript with a `.d.ts`, because a site's `astro.config` loads it straight from `node_modules`, where Node does not strip TypeScript |
| `src/icons/` | Tabler icons copied unchanged, inlined as SVG components at build time. The handoff fetches them from Iconify at runtime, which the system avoids |
| `guidelines/` | Specimen pages. The only copy: the personal site's `/ds/` serves these files from the installed package |

## Tokens and Terrazzo

- Chinese descriptions live in `$extensions["cafe.rottenth"]`. The key is the owner's domain reversed, the form the DTCG spec recommends for extension keys; keep it.
- The dark theme and the narrow viewport each emit only their own tokens through a permutation `include` built by `tokenIds()` in `terrazzo.config.ts`. Terrazzo's `only` option does not limit the output, and `sets: []` breaks aliases ("Could not resolve alias").
- `omitTypographyShorthand: true` is needed: the shorthand Terrazzo writes refers to its default sub-value variable names, which `subValueVariableName` renames.

## Components

- Port each component from the handoff's `.jsx` with the same props. Where a prop cannot work without React state, or a native element does the job, change it and say so in the component's header comment and on its docs page. Current examples: `Admonition`'s `details` is a native `<details>`; `Tooltip` also opens on a tap; `Abbreviation` leaves out `title`.
- Interactive components define a custom element in their `<script>` (`ds-spoiler`, `ds-tooltip`) and guard `customElements.define` with `customElements.get`, since a page can include a component many times.
- Scoped styles do not reach slot content or other components' elements; select those with `:global()` under one of the component's own classes.
- An Astro component cannot pass props to its children. `Steps` numbers its items with a CSS counter, and the `:::steps` directive works out each `Step`'s status itself.
- In MDX, a named slot is filled with an element carrying `slot="..."`. The plugin writes `<div slot="title">` for a step's title, so the title keeps its links and code.

## The directive plugin

- `remark-directive` reads any ASCII colon followed by a letter or digit as a text directive, so `10:30` contains a directive named `30`. The plugin puts the original text back for any directive it does not handle, and warns only when the name starts with a letter.
- It rewrites the tree from the leaves up, so a directive inside another is handled first.
- Tests run with `node --test` in the system's folder. Run the plugin over the personal site's posts after changing it.

## Docs site

- Languages are folders, `en/` and `zh/`, with the same file paths; Starlight pairs translations by path. A system's section sits inside each language folder.
- Page URLs end in a slash and the site is served under `/design-system/`, so links between pages are relative: `../tokens/`, not `./tokens`.
- In the sidebar config, a `slug` has no language prefix (`personal-website/components/steps`), and its label comes from the page's title in each language.
- The root redirect is Astro's `redirects` option with the base written out: `"/": "/design-system/en/"`.
- Starlight renders `:::note`, `:::tip` and `:::caution` as its own asides. Docs pages show a system's directive syntax in code blocks and render the component through an example page instead.
- Component examples are pages in `docs/src/pages/examples/<system>/` on `ExampleLayout`, which loads only the system's CSS. The `Example` component embeds one in an iframe, copies Starlight's `data-theme` into it and sizes it from the example's `<html>` height.
- A component page follows the structure in `docs/src/content/docs/en/spec/components.md`, and links to the source instead of listing props.
- Two build warnings are expected and harmless: the missing `i18n` collection (Starlight ships the Chinese interface text) and `Entry docs → 404 was not found`.
